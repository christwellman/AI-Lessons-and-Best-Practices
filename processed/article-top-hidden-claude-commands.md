## Summary

You can use prompt shortcuts as custom commands to avoid writing long instructions repeatedly. Build a small command library for tasks like research, criticism, and summarization. Define the exact behavior of each command instead of using simple keywords for better results.

## Key Takeaways

- Most users underuse AI by repeating long instructions for frequent tasks.
- Custom prompt shortcuts act as a personal command library for your workflow.
- Simple keywords are less reliable than detailed instruction definitions.
- Define your commands with specific constraints to get better results.
- Build a small set of commands for repeatable thinking patterns.

Many of these are better understood as prompt shortcuts, not official Claude commands.

The idea is still useful because most people underuse AI by repeatedly writing the same long instructions for tasks they perform over and over again. Instead, you can build your own command library around your workflow.

For example:

/focus

Complete only the requested task. Avoid unrelated suggestions, unnecessary explanations, and scope expansion.

/brief

Give me the answer in no more than three concise lines.

/matrix

Compare the available options in a structured table using clear decision criteria.

/devil

Challenge my current assumption. Present the strongest opposing argument and explain what evidence would support it.

/roast

Critically review the work. Identify weak reasoning, unsupported claims, missing evidence, and unnecessary complexity.

/silent

Deliver the finished output directly without explaining every intermediate step.

/humanize

Rewrite the content so it sounds natural, specific, conversational, and less formulaic.

/reverse

Deconstruct a successful result. Identify the decisions, assumptions, structure, and techniques that likely made it work.

/structured

Analyze the problem systematically. Consider the relevant factors before presenting the final recommendation.

/prototype

Turn the idea into a visual, interactive, or reusable artifact when the AI's capabilities support it.

Claude's Artifacts feature can create substantial standalone outputs, including documents, code, diagrams, websites, and interactive components.

But there is an important distinction. The commands shown in graphics like this should not automatically be treated as official built in Claude slash commands. The more reliable approach is to define the behavior yourself.

For example, instead of simply writing:

/devil

You could define it as:

"Challenge my proposal as a skeptical security architect. Identify the three strongest objections, explain the evidence behind each one, and tell me what evidence would change your conclusion."

That is far more reliable than expecting a single keyword to magically produce the same quality every time. The keyword becomes a shortcut for a much more detailed instruction. And that leads to the bigger lesson: AI productivity does not come from discovering magic commands. It comes from turning repeatable thinking patterns into repeatable instructions. If you regularly perform the same types of work, build a small command library around them.

Research.

Criticism.

Comparison.

Summarization.

Brainstorming.

Security review.

Decision making.

Content rewriting.

Data analysis.

You don't need 50 clever commands.

You need a small set of commands that capture how you want AI to approach the work you perform repeatedly.

That's when AI starts becoming less like a chatbot you have to repeatedly instruct and more like a system built around the way you actually work.
